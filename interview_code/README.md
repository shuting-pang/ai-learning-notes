# 面试代码与复盘

记录面试中遇到的实现题，以及实现背后的复杂度、边界情况和追问。

## 1. 冒泡排序

代码：[bubble_sort.py](bubble_sort.py)，入口函数为 `Bubbles(nums)`。

**问题：手写冒泡排序，并说明时间和空间复杂度。**

相邻元素逆序时交换；第 i 轮结束后，当前最大元素已移动到未排序区间的末端，因此下一轮可以少比较一个位置。

| 项目 | 当前实现 |
| --- | --- |
| 最好时间 | O(n²) |
| 平均时间 | O(n²) |
| 最坏时间 | O(n²) |
| 辅助空间 | O(1)，不计输入与命令行输出 |
| 稳定性 | 稳定：只在左侧元素严格大于右侧元素时交换 |
| 是否原地 | 是，会修改传入列表 |

当前代码没有“本轮是否发生交换”的标志，因此即使输入已经有序，仍会执行 n(n−1)/2 次比较，最好情况也是 O(n²)。

### 常见追问

- **怎样让最好情况达到 O(n)？** 每轮设置 `swapped = False`，交换时置为 True；若一轮结束仍为 False，说明已经有序，可以提前退出。最坏情况仍为 O(n²)。
- **为什么排序稳定？** 相等元素不会直接交换。若把判断改成 `>=`，就可能破坏稳定性。
- **空列表、单元素和重复值能否处理？** 可以；循环自然跳过无须比较的情况。
- **返回新列表吗？** 当前实现返回的是原列表对象。若先复制输入再排序，复制本身需要 O(n) 空间。

## 2. 多头自注意力

代码：[multihead_attention.py](multihead_attention.py)。这是基础的 dense self-attention 实现；残差连接、LayerNorm 和前馈网络不在这个模块中。

**问题：用 PyTorch 实现 multi-head self-attention，并说明张量形状和复杂度。**

记 B 为批量大小、L 为序列长度、d 为 `d_model`、h 为头数，每头维度 dₖ = d/h。

```text
输入 x                 [B, L, d]
线性投影 Q / K / V     [B, L, d]
拆分多头                [B, h, L, dₖ]
QKᵀ / sqrt(dₖ)         [B, h, L, L]
softmax 后乘 V          [B, h, L, dₖ]
拼接并输出投影           [B, L, d]
```

### 计算复杂度

| 部分 | 时间复杂度 |
| --- | --- |
| Q、K、V 线性投影与输出投影 | O(BLd²) |
| QKᵀ 和 attention × V | O(BL²d) |
| 完整前向计算 | O(BLd² + BL²d) |

常说的 O(L²d) 主要指单个样本的注意力矩阵计算，不包含全部线性投影成本。不能直接把它当作完整模块在所有配置下的成本。

- **激活空间**：O(BhL² + BLd)。当前实现显式保存每个头的 L×L 注意力矩阵，长序列时它往往是主要显存开销。
- **参数量**：代码有四个带 bias 的 d→d 线性层，共 4d² + 4d 个可训练参数。
- **头数的影响**：固定 d 时，h·dₖ = d，注意力矩阵乘法的总计算量仍为 O(BL²d)，不是再额外乘一个 h；显式注意力矩阵的存储则与 h 成正比。

### 常见追问

- **为什么除以 sqrt(dₖ)？** 限制点积随维度增大而增长的尺度，避免 softmax 过度饱和。
- **为什么要求 d 能整除 h？** 当前实现将嵌入维度平均拆到各个头中。
- **为什么 transpose 后要 contiguous？** 当前代码随后使用 `view` 合并多头，需要相容的内存布局；也可以结合实际布局使用 `reshape`。
- **mask 的形状是什么？** 当前实现的 mask 必须能广播到 `[B, h, L, L]`；例如因果 mask 用 `[1, 1, L, L]`，padding mask 可用 `[B, 1, 1, L]`。代码中 0 表示屏蔽。
- **全部 key 都被屏蔽会怎样？** 一行 logits 全为负无穷时，直接 softmax 可能产生 NaN；构造 mask 时需要避免或显式处理这一情况。
- **self-attention 和 cross-attention 的区别？** 当前 Q/K/V 都来自 x；cross-attention 的 Q 来自一组输入，K/V 来自另一组输入，其注意力成本与查询长度和键长度的乘积有关。
